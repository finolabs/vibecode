# Troubleshooting

Read the shared rules in [map.md](map.md#rules). Match the user's problem to one row, give the fix, and read the named skill's `SKILL.md` before going deeper. When no row fits, say so and offer the Explain mode for the skill involved.

| Problem | Fix |
| --- | --- |
| A script stops on Windows with a message about the platform | Native Windows is not supported: the scripts rely on POSIX file APIs. Run Claude Code, Codex or Antigravity with the plugin under WSL. The hooks never block a session on Windows. |
| The plugin's skills or hooks do not show up after installing | Plugins load when a session starts: open a new session. |
| Codex asks to trust the hooks again, or they stop running, after an update | Every change of hook content makes Codex ask again. In a new session open `/hooks` and trust the plugin's hooks. |
| A delegated Codex run hangs for a long time and its log stops after `Reading additional input from stdin...` | `codex exec` was started with a stdin that never closes and waits for its end. `delegate_env.py` now closes the child's stdin itself; a command run without it needs `< /dev/null`. Stop the hung run and start it again that way. |
| A Codex reviewer reports `cannot-post: no-network` | Its sandbox reaches GitHub only through Codex's network proxy. Start the run with `-c sandbox_workspace_write.network_access=true -c 'features.network_proxy={enabled=true, domains={"api.github.com"="allow"}}'`; `post_review.py` keeps that loopback proxy for `gh`. |
| `/setup doctor` shows `antigravity posting rule: warn` | An Antigravity allow-rule for `post_review.py` points to a script this install no longer has (often a path from before a rename), so Antigravity's own review posts are denied. Run `/setup roles` and redo its Review posting step, which previews the new rule and asks before it changes anything. |
| Claude Code still runs the old version after `/update` | The host keeps the old copy loaded until a restart. Restart Claude Code, then run `/update` or `/update whats-new` to continue the checklist. |
| `/update` shows `stale`, or `available` is empty | The cache is refreshed in the background after 24 hours and read on a later startup; a stale or empty value is unknown, not proof the plugin is current. Start a new session later and check again. |
| `/update` prints nothing at all | The update check is off (`FNL_UPDATE_CHECK=off` stops the helper commands too) or a read failed. |
| Antigravity has no update command | Its update procedure is still unverified; `update` explains the gap and leaves the step to you. |
| The dashboard is empty or names a missing source | Consent not given: run `/setup metrics`. No events: the hooks need the whole plugin installed and a session started after consent. A missing ledger: see `delegate`. |
| `/afk start` stops and points to setup | Record the away rules first with `/setup afk`. |
| `/afk start` says `strict` was removed, or that the limits were removed | Your setup still holds lines from before 0.3.3 (`Mode: strict`, `Max runs`, `Max runtime minutes`, `Max actions per hour`); they are no longer read and the lease starts as usual. Nothing to do, or run `/setup afk` again to rewrite the section. Anything that must stay forbidden while you are away is a host deny rule (Claude Code permission rules, Codex sandbox and approval policy). |
| After upgrading, afk answers "afk refused: the recorded lease is invalid or was written before 0.3.3" | A lease started before 0.3.3 holds counters the new lease format does not read. Run `/afk stop`, then `/afk start`. |
| Under a lease an `afk.py` command is denied with a request digest, or the agent cannot end its turn | The afk permission hook (Claude Code) allows a lease command only alone and plain: `python3 -I <absolute afk.py path> <command> [args]`, as the `End a turn:` line of `/afk start` prints it, with no shell variable, `;`, quote or other shell syntax. Retry it in that form. |
| Under a lease the agent keeps going after it tried to stop | The afk stop hook (Claude Code) sends a turn back once until the session records `afk.py log --kind idle --session <id>` for its repository's current queue; a `parked` record closes one item, not the turn. `FNL_AFK_STOP=off` turns it off. |
| `afk.py log --kind idle` is refused | The repository's queue still has open items (the refusal names them), or no queue exists yet: finish or park each item, or run `afk.py goal` first, with an empty list when there is no work. |
| `afk.py stop` is refused | Only `/afk stop` ends the lease, with `stop --all`, because it ends it for every session; an agent whose work is done logs `idle`. |
| Under a lease a tool call is denied with a request digest | The afk permission hook answers host prompts while you are away: the agent settles it through afk "Decide" and records `--approve-request <digest>`, or parks it. `FNL_AFK_PERMIT=off` brings the host's prompt back. |
| `/afk start` warns that nothing blocks credential reads | Add Claude Code's deny rules for the credential floor with `/setup afk`, or run with an approval mode that asks. |
| `/setup doctor` (or `quota_probe.py status`) shows `reset passed at <time>` or `no plan limits` for an install | The pool's reset has passed, so the old percentage no longer counts: the next routing reads it again. `no plan limits` means a Claude install on API billing, which routing never excludes; it is read again after 7 days. |
| `checks.py run` waits for the heavy-job lock or gives up with exit 75 | That check is saved heavy, and a list saved before 0.3.3 is all heavy. Save it again with `/setup checks`: checks that name test modules are then saved light and run at once. A light check also exits 75 when memory pressure stayed critical up to the wait cap. |
| Claude Code refuses a Bash command with "Heavy-job gate: this command is listed as heavy" | You turned on the heavy-job gate. Run the command through `heavy_run.py run --label <label> -- <command>`; for one session set `FNL_HEAVY_GATE=off`, or take it out with `/setup delegation`. |
| The heavy-job gate stopped refusing heavy commands after an update | The hook points at the plugin copy you had when you turned it on. Run `/setup delegation` again to point it at the current copy. |
| `heavy_run.py` refuses a command with exit 77 | A pause marker is active. Run `/pause resume` once you are back from the restart; a marker older than 24 hours never blocks. |
| `/restore-point` says "Not a git repository" | It works in git repositories only and creates nothing. Run `git init` yourself if you want one. |
| A skill says a dependency is missing | It was installed on its own. Add the named skill, for example `npx skills add finolabs/vibecode --skill delegate`, or install the whole plugin. |
| The agent does not list `setup`, `status` or another typed skill | Those skills are typed by the user only and may be missing from the agent's own list; type the command yourself. |
