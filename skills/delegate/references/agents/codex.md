# Codex

How Codex is dispatched as a delegate, what ends its run, and how its result maps to a ledger outcome. Read [agents.md](../agents.md) first: its common procedure (brief lint, private log folder, `delegate_env.py`, hard-cap wrapper, residual risk) holds for every family.

- **Headless**: `python3 -I <this skill folder>/scripts/delegate_env.py --family codex -- codex exec -m <model> -c model_reasoning_effort=<level> -s workspace-write -C <worktree> -o <last-message-file> "$(cat "$B")"`. Add only the directories the build needs with `--add-dir`. Use `--json` when you want the event stream. Add `--ephemeral` for a one-shot run (review, advice, navigator, a small task with no rework round expected): it saves no session file, so nothing is left to archive and nothing can resume it; a task that expects rework rounds runs without it (advisory, agent judgment; `codex exec --help`, codex-cli 0.169.0). `codex exec` appends a piped stdin to the prompt and waits for its end: a log that stops after `Reading additional input from stdin...` is a run waiting on an open stdin, not working. `delegate_env.py` closes the child's stdin (script); a direct call needs `< /dev/null`.
- **Read-only work**: `-s read-only`. For a code review, `python3 -I <this skill folder>/scripts/delegate_env.py --family codex -- codex review --base <branch>` (or `--uncommitted`) runs Codex's own review flow; it saves a session, so a one-shot review uses `codex exec review --ephemeral --base <branch>` instead (`codex review` has no `--ephemeral` in 0.169.0).
- **Review and posting in the sandbox**: add `-c sandbox_workspace_write.network_access=true -c 'features.network_proxy={enabled=true, domains={"api.github.com"="allow"}}'` and `--add-dir` for the posting folder; `post_review.py` keeps Codex's loopback proxy for `gh` (script), so the reviewer posts without leaving the sandbox. Without the proxy override it reports `cannot-post: no-network`.
- **Unsandboxed review and posting** (advisory, agent judgment), only where the sandbox form cannot post: start `codex exec` with `-s danger-full-access` only for review and posting, never implementation. This is allowed only with a brief that is read-only except for the one posting command and passes `brief_check.py`; the posting helper needs network access and the git credential helper. Record the dispatch in the ledger as usual. The brief check is script-enforced; the run's scope is agent judgment.
- **End of run**: the exit status and the last-message file. Approvals cannot be granted in a headless run: an action that needs one fails.
- **Outcomes** (advisory, agent judgment): a dispatch ended by a command needing permission is `needs-permission`, never `quota`. Record `quota` only when the agent reported a limit; a `turn.failed`/`error` event alone is insufficient.
- **Rework**: a new `codex exec` in the same worktree with a short follow-up brief that names each defect and points at the original brief; prefer it over resuming a long run. After an `--ephemeral` run this is the only way: the new brief carries the earlier findings and the diff (or the head to diff against), since the earlier session was never saved.
- **Saved sessions**: `ledger.py finish --log-path <log>` records `codex_thread`, a digest of the session id the log names, never the id. After the dispatch is accepted and its pull request merged, run `ledger.py codex-threads --dispatch <id>` and run each `codex archive <id>` line it prints (advisory, agent judgment; the ledger cannot see a forge). Archiving moves the session to Codex's `archived_sessions` folder and `codex unarchive` restores it. Never delete a session or its file: `codex delete` and removing files under `~/.codex/sessions` cannot be undone and break resume.
