# Verification judgments

Every semantic check uses [scripts/judge.py](../scripts/judge.py). The judge is the host's small model; the script makes no network call and reads no API key. A `## Assignment matrix` `Judge:` line (`jev` or `host`) still parses and both values mean the host model; `--judge jev` and a matrix `Judge: jev` read as host with one retirement line on stderr (Jev was retired on 26/11/2026). `judge.py ask --question <English statement> --evidence-file <file>` screens the fields and exits 3 (`unavailable`): the host model supplies the answer for `check-host`. `--site` chooses one of `verification` (default), `navigator`, `compaction` or `delegation`. The choice site `away-evaluation` (with `--option`) and the `check-table` command serve only afk's decide procedure (the table must carry `source: host-small`); verification never uses them. Closed field caps and a 64 KiB body cap apply; a secret or machine-path hit refuses the question and reports only the field name. `--dry-run` prints payload field names and sizes.

The host judge is a small model on the host's fast tier; the script never calls it. Give it the same question and evidence, treated as data, and ask for `answer: yes|no|insufficient` plus a verbatim supporting `quote` for `yes` (advisory, agent judgment). `judge.py check-host --answers <json file> --evidence-file <file>` changes an unquoted or misquoted `yes` into `insufficient` (script-enforced). Quotes need at least 8 trimmed characters and 8 alphanumeric characters; punctuation-only quotes are refused. A quote's presence alone cannot prove support. `judge.py ask` exit 3 means the script holds no answer: the coordinator supplies the small host answer with the same payload (advisory, agent judgment).

The first verification run saves the question/evidence packet with owner-only permissions when `--requests-out` is given; this is a private local work artifact, never plugin state or an event. Produce a host answers JSON object keyed by criterion identifier, each containing `answer`, `quote`, `question` and `evidence_sha256` copied from that packet. Then run:

```text
python3 -I <this skill folder>/scripts/verify_claim.py --complete-host <saved request packet> --host-answers <answers json> --head <same head> --ledger-id <same dispatch id> --checkout <task checkout>
```

This attaches checked answers to the exact test run without rerunning tests with potentially different timing output; packet digest, question, evidence, checkout and head must match (script-enforced). Keep both the original criterion and its English restatement in the coordinator report for criteria in another language (advisory, agent judgment); receipts store neither. For an agreement measurement, `judge.py validate --cases <json> [--answers <host json>]` runs one harness over the same supplied cases and prints counts and per-case answers; it stores nothing. Cases contain `id`, `question`, `evidence`, `expected`; host answers are keyed by case id. Use known outcomes from merged pull requests by independent authors before trusting the judge (advisory, agent judgment). The current experiment and synthetic tests do not establish that validation: reports stay labelled `unvalidated`. Read every `no` and `insufficient`; the judge grants no acceptance, and `yes` never replaces mechanics (advisory, agent judgment).
